## 1. T4Formalization: the cascade belongs to the graph

A queue fails alone. A network fails in the order its edges allow, and the difference is not one of size. Layer 02 could bound a wait because the object was one server with one waiting room; here the object is a set of nodes, a set of links, and a rule that moves load across the links when a node drops out. The formalization site is the one that makes the coupling explicit enough to reason about, and what it produces first is a negative claim with teeth: the cascade is a property of the coupling graph, not of the components. Every node can meet its own specification and the collection still fail, because failure travels down a path and no node in it is a path.

The mechanism is redistribution. Take a node $i$ carrying load $L\_{i}(0)$ with capacity $C\_{i}$, and give it a tolerance

$$\alpha\_{\mathrm{tol}} = \frac{1-\rho\_{i}}{\rho\_{i}},$$

where $\rho\_{i} = L\_{i}(0)/C\_{i}$ is its load factor, so that the tolerance is the reciprocal of the load factor less one, and a node is safe against an increase of that fraction of its load and no more. The capacity that survives a redistribution is then

$$C\_{i} = (1+\alpha\_{\mathrm{tol}})\mkern3mu L\_{i}(0),$$

which is the criterion Motter & Lai (2002) use to define the surviving set after a removal: a node fails when the load it receives exceeds this capacity, the load it carried is redistributed to its neighbours, and the procedure repeats. Two properties of that construction matter more than any particular run of it. The tolerance is fixed by the operating point and not by the component: the same hardware is tolerant when idle and fragile when busy, because $\alpha\_{\mathrm{tol}}$ falls as $\rho\_{i}$ rises. The criterion is also recursive, so the removal set is not the set of nodes that depend on the failed node but the set that the redistribution reaches: a neighbour is at risk because it was near capacity, not because it was near the failure.

The graph does the rest. If the load of a failed node carrying load $L$ is spread equally over $z$ neighbours that also carry baseline load $L$, each neighbour receives an additional $L/z$ and fails when $L(1 + 1/z) > L/\rho$, that is, when its baseline load factor $\rho$ exceeds $z/(z+1) = 1 - 1/(z+1)$: a single neighbour takes the whole load and fails above $\rho = 1/2$, while each additional link raises that per-neighbour breakdown threshold with diminishing increments $\frac{1}{z(z+1)}$ and simultaneously opens another edge along which a supercritical overload can propagate. A topology that is one failure deep is therefore not half as robust as a topology that is two failures deep; robustness is not additive in the number of links, and a redundant link is a conductor as well as a spare. This is the formal content the order contributes to the architecture, and it is a content about shape: given the graph, the loads and the capacity rule, the criterion returns the surviving set exactly.

What a formal criterion can certify is bounded by what it was given. It can certify that a stated removal set does not cascade under the stated redistribution rule with the stated loads. It cannot certify that the graph is the graph: the links that carry load in an emergency are frequently not the links in the diagram, and a description that omits a shared dependency omits the edge the cascade will use. It cannot certify that the loads are the loads, because a load is a rate and a rate is a model quantity, as §1 of the previous chapter established. And it cannot certify anything about time. The next site is not optional.

## 2. T5Temporal: the race between propagation and response

A cascade is a race, and the race is decided by a ratio, not by a magnitude. Let $\tau\_{p}$ be the time a failure takes to load the next node in the path and $\tau\_{r}$ the time between the first symptom and an effective response. A path of $k$ edges delivers the failure to its far end at $k\mkern3mu\tau\_{p}$, so the cascade is contained before the far end if $\tau\_{r} < k\mkern3mu\tau\_{p}$ and is not contained if the inequality runs the other way. Everything in that comparison is a duration, and the ratio $\tau\_{r}/\tau\_{p}$ is what the order reads: it counts how many edges the response can afford to be late by. A topology is therefore never safe or unsafe as such. It is safe against a response of a given latency, and the same graph that absorbs a failure at one horizon exports it at another.

The two durations are not measured the same way. Propagation is fast and mechanical: a redistribution follows from the capacity rule, and its delay is a switching and queueing delay that the design can name. Response is slow and organisational: detection requires that a symptom be read as a symptom, and the reading competes with the ordinary work of the units that must act. Perrow (1984) names the combination that makes this lethal: tight coupling, where one failure propagates quickly, joined to interactive complexity, where the symptom is not legible as its cause. Neither property is a defect. Tight coupling is what buys the throughput, complexity is what buys the function, and the pair is a design choice that has already been made by the time anyone asks about the horizon.

Bronson et al. (2021) describe the case in which the response never wins because the system has no stable state to return to: a trigger degrades a service, the degraded service sheds load onto a retry path that keeps the load in place after the trigger is gone, and recovery requires an intervention that the system's own saturation prevents. The mechanism is not a race that was lost once; it is a race that restarts, so the relevant quantity is not the latency of a single response but the ratio of the recovery time to the interval between triggers. Scheffer et al. (2009) give the same structure a signature: as a system approaches a transition, its recovery from small perturbations slows, so the return time lengthens before the transition occurs. A return time is measurable, and it lengthens while everything else looks unchanged. That is what makes the temporal site a site and not a warning.

Holling (1973) had already separated the two quantities that a single word conflates: a system can be stable in the sense of returning quickly to a neighbourhood and resilient in the sense of absorbing a disturbance before its structure changes, and the two do not vary together. A topology tuned for the first is not thereby tuned for the second, because a fast return can be fast precisely by shedding the part of the structure that made the disturbance absorptive. What the temporal site contributes is the discipline of asking which of the two a design is buying, and at what horizon the answer was computed.

## 3. T6Performative: the measurement is the edge

The graph of §1 was given. In an institution it is made, and it is often made by the act of monitoring. Two units that report to one dashboard, are ranked by one ratio, and are alerted by one threshold are one system for the purposes of a cascade, whether or not any link appears between them in the design. The metric is the edge: load moves along it because a degraded reading in one unit changes what the other unit is asked to do, and the change is as effective as a cable. This is the governance site of the order, and its content is that the coupling is a decision about description and not a fact about wiring.

Commensuration is the mechanism. Espeland & Stevens (1998) describe what happens when unlike quantities are given one scale: the scale does not merely compare, it constitutes a relation where there was none, and the relation persists after the comparison is forgotten. Bowker & Star (1999) show the same work in classification, where a category that spans two practices makes them accountable to one another, and the accountability is the channel. March & Simon (1958) had put it in the minimal form: organisations are coupled by the information they must share to decide, so a shared input is a shared fate. A single service-level figure computed over two teams does not measure their dependence; it creates one, because the figure cannot be met by either team alone.

The consequence is that the formalization of §1 can be exact about a graph that the reporting regime has already replaced. The diagram has one topology, the metric has another, and the cascade follows the second. A redundancy that is not visible in the report is not redundancy for the purposes of response, since no one will route load along a link that no number mentions; and a dependence that exists only in the report is a real dependence, since load will be moved to protect a figure that no physical link connects. Goodhart (1975) supplies the direction of the drift: a measure used for control stops being a good measure of what it measured, and in a coupled system it stops being a good measure of the coupling while becoming the coupling.

There is a repair available at this site, and it is a governance repair, not a technical one. If the edge is a reporting relation, then the edge can be drawn deliberately: a metric defined over the units whose fates are already joined makes the coupling legible and therefore available to the response of §2, while a metric defined over a unit that is physically coupled but administratively separate hides the edge until the cascade uses it. Which of the two an institution has is not a property of its network. It is a property of its accounts, and the accounts are the thing a governance site can change.

## 4. The signature: two vitals and one description

The signature is $(0, 2, 1)$: no epistemic site, two vital, one governance. The two vital readings are the sites of §1 and §2, and they are vital in the strict sense: each carries a margin that can be provisioned. The tolerance $\alpha\_{\mathrm{tol}}$ is a quantity of capacity held against a redistribution, and the ratio $\tau\_{r}/\tau\_{p}$ is a quantity of time held against a propagation; both are resources, both can be spent, and both can be reported as the thing that would have to be bought. The governance reading is the performative site, and its office is the definition of the metric — the one place in this order where a decision is made by someone who can be asked about it.

What is absent is again an epistemic site, and the absence is not the same absence as in Layer 02. There the order had one vital margin and spent its governance on liability: the question it could answer was who pays for the buffer, and the question it could not answer was whether its model of arrivals was the right model. Here the order has two vital margins and spends its governance on description: it can say how much tolerance a graph has and how much time a response has, and it can say who drew the metric. What it cannot do is check the description against anything. The graph it reasons over is the graph it was given, the loads are the loads it was told, and no site in the order requires either to be declared as an estimate with an error attached.

The cost is specific. A topology that passes the criterion of §1 and meets the horizon of §2 is certified against a description, and the certification is only as good as the description's completeness; a missing edge is invisible in the arithmetic and decisive in the event. The cost is also that the order has no liability reading at all, so the two margins it holds have no owner. Nothing in the signature allocates the consequence of a cascade to the party that chose the coupling, which means the incentive to invest in tolerance is supplied from outside the order or not at all — and the performative site, being the only office present, will be the one asked to supply it. That is how a metric becomes a substitute for a margin.

What the absence does not cost is the two margins themselves. Unlike an axial exposure that leaves only a formula, this one leaves two provisionable quantities and one place where a person can be held to a definition. The order can be built on, and what it hands upward is a graph with a tolerance, a race with a ratio, and a coupling with an author. What it cannot hand upward is any statement about how wrong its graph is.

1. Derive $\alpha\_{\mathrm{tol}} = (1-\rho\_{i})/\rho\_{i}$ from the load factor, and explain why the tolerance is a property of the operating point and not of the component.
2. State the containment condition $\tau\_{r} < k\mkern3mu\tau\_{p}$ for a path of $k$ edges, and say why a topology has no safety independent of the horizon at which it is asked.
3. Show how a shared metric creates a coupling that the design diagram does not contain, and why that coupling is the one a cascade will follow.
